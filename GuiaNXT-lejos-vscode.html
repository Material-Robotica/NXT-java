Programar el NXT en Java con leJOS y VS Code

Instalación en Windows 11 (Ceibalita), conexión por Bluetooth, primer programa y herramientas útiles. Incluye cómo instalar el firmware leJOS en un NXT que todavía tiene el firmware de LEGO.

Qué se necesita

  • Un LEGO NXT con pilas o batería bien cargadas.
  • Los instaladores del JDK 8 de 32 bits y de leJOS NXJ, disponibles en el release instaladores-nxt del repositorio NXT-java.
  • Cable USB del NXT (solo para instalar el firmware leJOS, si el brick no lo tiene).
  • Computadora con Windows 11 y Bluetooth (las Ceibalitas lo tienen), con permisos de administrador para instalar.
  • VS Code con la extensión Extension Pack for Java (si no está instalado, ver el paso 5).

Antes de empezar: tres datos sobre leJOS NXJ

  • Las herramientas de leJOS NXJ para Windows son de 32 bits: necesitan un JDK 8 de 32 bits. Con un JDK de 64 bits no funcionan.
  • El lenguaje es Java estilo versión 5/6: no se pueden usar lambdas, var, streams ni muchas clases modernas de Java.
  • La conexión por USB depende de un driver de LEGO muy antiguo que suele fallar en Windows 11. Esta guía usa Bluetooth, que funciona sin drivers extra.

Cómo ejecutar los comandos de esta guía

Todos los comandos y scripts de esta guía se ejecutan en Windows PowerShell:

  1. Abrir el menú Inicio, escribir PowerShell y elegir Windows PowerShell.
  2. Copiar el comando o script con el botón Copiar de cada recuadro.
  3. Pegarlo en la ventana de PowerShell con clic derecho (o Ctrl + V) y presionar Enter. En los scripts de varias líneas, presionar Enter una vez más si el cursor queda esperando.

Cuando la guía indique «abrir una PowerShell nueva», cerrar la ventana y volver a abrirla, para que tome los cambios de las variables de entorno.

01

Comprobar qué Java hay instalado

Abrir Windows PowerShell (menú Inicio → escribir PowerShell), pegar este script completo y presionar Enter. Lista todos los Java de la computadora e indica, para cada uno, si es de 32 o 64 bits y si es JDK o solo JRE.

PowerShell
$bases = "C:\Program Files (x86)", "C:\Program Files", "C:\Java"
foreach ($base in $bases) {
  if (Test-Path $base) {
    Get-ChildItem $base -Recurse -Depth 4 -Filter java.exe -ErrorAction SilentlyContinue |
      Where-Object { $_.FullName -notmatch '\\jdk[^\\]*\\jre\\' } |
      ForEach-Object {
        $ver  = (& $_.FullName -version 2>&1) -join " "
        $bits = if ($ver -match "64-Bit") { "64 bits" } else { "32 bits" }
        $tipo = if (Test-Path (Join-Path $_.DirectoryName "javac.exe")) { "JDK" } else { "JRE" }
        "{0} | {1} | {2}" -f $bits, $tipo, $_.FullName
      }
  }
}
  • Si aparece una línea 32 bits | JDK con Java 1.8, ya está el JDK necesario: saltar el paso 2 y, en el paso 3, elegir esa carpeta.
  • Un JRE de 32 bits no alcanza (no tiene javac). El que está en OpenRobertaNXT\java pertenece al programa USB de Open Roberta: no usarlo ni modificarlo.
  • Los JDK de 64 bits (17, 21) pueden quedar instalados: no interfieren.
02

Instalar un JDK 8 de 32 bits

Descargar el instalador .msi del JDK 8 de 32 bits (Temurin) desde el release instaladores-nxt del repositorio Material-Robotica/NXT-java, en la sección Assets.

Alternativa · sitio oficial

Si el release no está disponible, entrar a adoptium.net y elegir versión 8 - LTS, sistema Windows y arquitectura x86.

La página muestra Unsupported Platform: Windows de 32 bits ya no recibe actualizaciones de seguridad. Para este uso el riesgo es muy bajo, porque ese JDK solo lo usan las herramientas de leJOS. Hacer clic en Show downloads anyway, dejar seleccionado JDK y descargar el .msi.

En el instalador, cambiar la ubicación a:

ubicación
C:\Java\jdk8-32\

En la misma pantalla, ajustar las opciones (clic en el ícono de cada una):

OpciónElegirMotivo
Añadir al PATHNo disponible ✗Evita que java en la terminal abra este JDK en lugar del 17 o 21.
Asociar .jarNo disponible ✗Los .jar se siguen abriendo con el Java moderno.
Establecer la variable JAVA_HOMENo disponible ✗No cambia la configuración de Java Web.
Claves de registro JavaSoftSe instalará ✓El instalador de leJOS encuentra el JDK solo. El aviso sobre javapath afecta solo al Java de Oracle.

Al terminar, verificar en PowerShell:

PowerShell
& "C:\Java\jdk8-32\bin\javac.exe" -version    # debe mostrar javac 1.8.0_...
03

Instalar leJOS NXJ 0.9.1beta-3

Descargar leJOS_NXJ_0.9.1beta-3_win32_setup.exe desde el release instaladores-nxt del repositorio Material-Robotica/NXT-java, en la sección Assets.

Alternativa · SourceForge

Si el release no está disponible, descargarlo de SourceForge con este enlace directo. Ahí el botón verde Download Latest Version descarga leJOS para EV3, que no sirve para el NXT.

enlace de descarga
https://sourceforge.net/projects/lejos/files/lejos-NXJ/0.9.1beta/leJOS_NXJ_0.9.1beta-3_win32_setup.exe/download

Comprobar que el archivo descargado se llame leJOS_NXJ_0.9.1beta-3_win32_setup.exe y pese unos 21 MB (el de EV3 pesa unos 27 MB).

  1. Ejecutar como administrador. Si aparece SmartScreen: Más información → Ejecutar de todas formas.
  2. En Select a Java Development Kit, seleccionar la carpeta C:\Java\jdk8-32 (la carpeta raíz, no bin).
  3. Dejar la carpeta de instalación por defecto: C:\Program Files (x86)\leJOS NXJ.
  4. En Select Components, marcar también Sample and Example Projects (ejemplos útiles como referencia). Dejar marcada la documentación.
  5. Al final se abre NXJ Flash. Si el NXT ya tiene leJOS, cerrar la ventana sin flashear: flashear borra todos los programas del brick. Si no lo tiene, cerrarla igual y seguir el paso 6.
04

Verificar las variables de entorno

Cerrar todas las terminales, abrir una PowerShell nueva y ejecutar:

PowerShell
$env:NXJ_HOME               # C:\Program Files (x86)\leJOS NXJ
$env:LEJOS_NXT_JAVA_HOME    # C:\Java\jdk8-32
nxjc -version               # javac 1.8.0_...

El instalador crea estas variables. LEJOS_NXT_JAVA_HOME hace que leJOS use el JDK de 32 bits aunque JAVA_HOME apunte a otro JDK. Si alguna sale vacía, crearla en Editar las variables de entorno del sistema.

Alternativa

Si no se pueden crear variables del sistema (por ejemplo, sin permisos de administrador), se pueden definir solo para la terminal de VS Code, agregando esto al settings.json del proyecto (paso 8):

fragmento de settings.json
"terminal.integrated.env.windows": {
  "NXJ_HOME": "C:\\Program Files (x86)\\leJOS NXJ",
  "LEJOS_NXT_JAVA_HOME": "C:\\Java\\jdk8-32",
  "PATH": "C:\\Program Files (x86)\\leJOS NXJ\\bin;${env:PATH}"
}
05

Instalar VS Code y la extensión de Java

Si VS Code ya está instalado, pasar directamente a la parte de la extensión.

  1. Descargar el instalador desde code.visualstudio.com/download: opción Windows → User Installer x64. No requiere permisos de administrador.
  2. Durante la instalación, en Seleccione las tareas adicionales, dejar marcada Agregar a PATH (permite abrir VS Code con el comando code, que usa el script del paso 8). Las opciones Agregar la acción «Abrir con Code» son opcionales pero cómodas.
  3. Terminar la instalación y cerrar todas las ventanas de PowerShell para que reconozcan el comando code.
Alternativa · una sola línea

Si la computadora tiene winget (incluido en Windows 11), se puede instalar desde PowerShell:

PowerShell
winget install --id Microsoft.VisualStudioCode -e --scope user

Instalar la extensión de Java. En una PowerShell nueva:

PowerShell
code --install-extension vscjava.vscode-java-pack

También se puede instalar desde VS Code: ícono de Extensiones en la barra lateral (o Ctrl + Shift + X), buscar Extension Pack for Java (de Microsoft) e Instalar. El paquete incluye el soporte de lenguaje de Red Hat y el depurador.

La extensión trae su propio Java interno para funcionar, así que no hace falta instalar otro JDK además del JDK 8 de 32 bits.

Listo si

code --version muestra un número de versión y, en VS Code, la extensión aparece como instalada.

06

Instalar leJOS en el NXT (si no lo tiene)

Encender el NXT y mirar la pantalla. Si aparece el menú de leJOS (con opciones como Files, Bluetooth, System), ya tiene el firmware: pasar al paso 7. Si aparece el menú original de LEGO (My Files, NXT Program, View…), hay que instalarlo.

Antes de empezar
  • Instalar el firmware leJOS borra todos los programas y archivos guardados en el NXT.
  • Un NXT con leJOS no funciona con Open Roberta ni con el software de LEGO. Para volver a usarlo allí hay que reinstalar el firmware de LEGO desde el software LEGO MINDSTORMS NXT.
  • Usar pilas nuevas o la batería recién cargada: si el NXT se apaga durante el proceso, hay que repetirlo.
  • El firmware se instala solo por USB y necesita el driver Fantom (incluye el driver de actualización de firmware de LEGO). Está en el release instaladores-nxt del repositorio Material-Robotica/openRoberta-NXT.
  1. Conectar el NXT por USB y encenderlo.
  2. En PowerShell, abrir el programa de instalación del firmware:
PowerShell
nxjflashg
  1. En la ventana Install leJOS NXJ Firmware, hacer clic en Flash leJOS firmware y aceptar las confirmaciones.
  2. Si el programa pide poner el NXT en modo de actualización de firmware: con un clip, presionar el botón de reset que está dentro del orificio de la parte trasera del NXT, junto al puerto USB, durante más de 4 segundos. La pantalla queda en blanco y el NXT emite un tictac suave: eso indica que está en modo de actualización.
  3. Esperar a que la barra de progreso llegue al 100 %. El NXT se reinicia solo y muestra el logo y el menú de leJOS.

Después de instalarlo, preparar el NXT para el Bluetooth del paso 7:

  • En el menú Bluetooth, dejar Power encendido y Visibility activada.
  • El PIN por defecto es 1234.
Si el USB no funciona

Si al ejecutar nxjflashg aparece el error cannot load library ... jfantom.dll, Windows 11 está bloqueando el driver Fantom (ver la sección «Usar USB en lugar de Bluetooth»). Como el firmware se instala una sola vez por brick, las opciones son:

  • Hacer la instalación en otra computadora donde el USB del NXT funcione (por ejemplo, con Windows 10) y después volver a la Ceibalita para programar por Bluetooth.
  • Desactivar temporalmente la Integridad de memoria (Seguridad de Windows → Seguridad del dispositivo → Aislamiento del núcleo), reiniciar, instalar el firmware y volver a activarla al terminar, con otro reinicio.
Si algo sale mal

Si el proceso se corta (cable desconectado, pilas agotadas), el NXT puede quedar con la pantalla en blanco haciendo tictac. No está dañado: el modo de actualización está grabado de fábrica y no se borra. Volver a ejecutar nxjflashg y repetir la instalación.

↑ índiceConexión por Bluetooth

07

Emparejar el NXT con la computadora

  1. Encender el NXT y, en el menú Bluetooth de leJOS, verificar que esté encendido y visible.
  2. En PowerShell, ejecutar nxjbrowse.
PowerShell
nxjbrowse

Primero aparece un error Failed to load USB comms driver: es esperable si no hay driver USB y puede ignorarse. Después leJOS busca por Bluetooth y abre la ventana NXJ File Browser con una fila NXT | Bluetooth | ... | DISCONNECTED.

  1. Seleccionar la fila y hacer clic en Connect.
  2. Windows abre Emparejar el dispositivo: usar el PIN 1234. Puede figurar como «Dispositivo desconocido»; no es un problema.
  3. Volver a hacer clic en Connect. Se abre la lista de archivos del NXT (vacía si no tiene programas).
  4. Cerrar la ventana del File Browser. Mientras está abierta ocupa la conexión y no se pueden subir programas.
Recomendado

Con Set Name se le puede poner un nombre al NXT (por ejemplo, NXT-Java) para distinguirlo de otros NXT cercanos. El emparejamiento se hace una sola vez por computadora.

08

Crear el proyecto con un script

Este script crea la carpeta Documentos\nxt-hola con su estructura y archivos, y la abre en VS Code. Copiarlo completo, pegarlo en PowerShell y presionar Enter.

PowerShell
$base = "$env:USERPROFILE\Documents\nxt-hola"
New-Item -ItemType Directory -Force -Path "$base\.vscode", "$base\nxt-bin", "$base\src" | Out-Null

$settings = @'
{
  "java.project.sourcePaths": ["src"],
  "java.project.referencedLibraries": [
    "C:/Program Files (x86)/leJOS NXJ/lib/nxt/classes.jar"
  ]
}
'@

$tasks = @'
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "NXT: Compilar",
      "type": "shell",
      "command": "nxjc -d nxt-bin -sourcepath src \"${file}\"",
      "problemMatcher": []
    },
    {
      "label": "NXT: Subir y ejecutar",
      "type": "shell",
      "command": "nxj -b -r -cp nxt-bin ${fileBasenameNoExtension}",
      "dependsOn": "NXT: Compilar",
      "group": { "kind": "build", "isDefault": true },
      "problemMatcher": []
    },
    {
      "label": "NXT: Solo subir",
      "type": "shell",
      "command": "nxj -b -cp nxt-bin ${fileBasenameNoExtension}",
      "dependsOn": "NXT: Compilar",
      "problemMatcher": []
    }
  ]
}
'@

$hola = @'
import lejos.nxt.Button;
import lejos.nxt.LCD;
import lejos.nxt.Motor;
import lejos.nxt.Sound;

public class HolaNXT {
    public static void main(String[] args) {
        LCD.drawString("Hola NXT!", 0, 0);
        LCD.drawString("Pulsar boton", 0, 2);
        Button.waitForAnyPress();

        Motor.B.setSpeed(360);
        Motor.C.setSpeed(360);
        Motor.B.rotate(720, true);
        Motor.C.rotate(720);

        Sound.beep();
        LCD.clear();
        LCD.drawString("Fin", 0, 0);
        Button.waitForAnyPress();
    }
}
'@

[System.IO.File]::WriteAllText("$base\.vscode\settings.json", $settings)
[System.IO.File]::WriteAllText("$base\.vscode\tasks.json", $tasks)
[System.IO.File]::WriteAllText("$base\src\HolaNXT.java", $hola)

code $base

Si code no se reconoce como comando, abrir VS Code y usar Archivo → Abrir carpeta → Documentos → nxt-hola. Si VS Code pregunta si se confía en los autores de la carpeta, responder Sí.

Estructura que queda creada:

nxt-hola/ ├── .vscode/ │ ├── settings.json → autocompletado con la biblioteca de leJOS │ └── tasks.json → compilar, subir y ejecutar ├── nxt-bin/ → clases compiladas por leJOS └── src/ └── HolaNXT.java
Importante

Los archivos se guardan con WriteAllText para que queden en UTF-8 sin BOM. Con Set-Content, el compilador de Java 8 da el error illegal character '\ufeff'.

09

Subir y ejecutar el primer programa

  1. Conectar los motores en los puertos B (izquierdo) y C (derecho).
  2. Encender el NXT y comprobar que el File Browser esté cerrado.
  3. Abrir src/HolaNXT.java en el editor y presionar Ctrl + Shift + B.

La terminal de VS Code muestra la compilación, la conexión por Bluetooth y la subida. En la pantalla del NXT aparece «Hola NXT!». Al pulsar un botón, el robot avanza dos vueltas de rueda, emite un pitido y muestra «Fin».

Opción de nxjSignificado
-bConectar por Bluetooth (-u sería por USB).
-rEjecutar el programa apenas termina de subirse.
-cp nxt-binCarpeta donde están las clases compiladas.
-n NXT-JavaOpcional: conectar solo con el NXT de ese nombre.
Instalar sin ejecutar

Para dejar un programa terminado guardado en el NXT sin que arranque, usar Terminal → Ejecutar tarea → NXT: Solo subir. Después se ejecuta desde el NXT, en el menú Files.

TareaCuándo usarla
Ctrl + Shift + B (Subir y ejecutar)Durante el desarrollo, para probar rápido.
NXT: Solo subirCon el programa terminado, para dejarlo instalado en el NXT.
Importante

No usar el botón Run de VS Code: compila con un Java moderno que el NXT no entiende. Compilar y subir siempre con Ctrl + Shift + B.

Para cada programa nuevo, crear un archivo .java en src con su propio main, tenerlo abierto en el editor y presionar Ctrl + Shift + B. La pantalla del NXT tiene 16 columnas y 8 filas, y no admite tildes ni eñes.

Opcional · conexión por USB

Usar USB en lugar de Bluetooth

Requiere el driver Fantom de LEGO (versión de 64 bits, disponible en el release instaladores-nxt del repositorio openRoberta-NXT), instalado como administrador y con reinicio. En el tasks.json, cambiar -b por -u.

En Windows 11 es frecuente que falle con el error cannot load library ... jfantom.dll / Error en una rutina de inicialización de biblioteca de vínculos dinámicos (DLL), aunque el driver esté instalado. La causa más probable es la Integridad de memoria (Seguridad de Windows → Seguridad del dispositivo → Aislamiento del núcleo), que bloquea los componentes antiguos de National Instruments. Desactivarla reduce la seguridad del equipo, por lo que se recomienda usar Bluetooth.

Problemas frecuentes

Si algo no funciona

«No NXT found» al subir
Revisar que el NXT esté encendido con el menú de leJOS, que tenga el Bluetooth encendido y visible, que esté emparejado (paso 7) y que la ventana del File Browser esté cerrada.
Se conecta a otro NXT
Ponerle nombre al NXT con Set Name en el File Browser y agregar -n NOMBRE al comando nxj del tasks.json.
«cannot find symbol» con una clase propia
La clase auxiliar no está en la carpeta src o el nombre del archivo no coincide con el de la clase (Robot.java → public class Robot).
Error al subir: la clase no tiene main
Se presionó Ctrl + Shift + B con una clase auxiliar abierta. Abrir el archivo del programa (el que tiene main) y repetir.
Error de librería nativa o de 32 bits
leJOS está usando un JDK de 64 bits. Verificar que LEJOS_NXT_JAVA_HOME apunte a C:\Java\jdk8-32 y abrir una terminal nueva.
«illegal character: '\ufeff'» al compilar
El archivo .java se guardó con BOM. En VS Code, hacer clic en la codificación de la barra inferior (UTF-8 with BOM) y elegir Guardar con codificación → UTF-8.
«Unsupported class version» al enlazar
Las clases se compilaron con un Java moderno (por ejemplo, con el botón Run de VS Code). Borrar el contenido de nxt-bin y volver a usar Ctrl + Shift + B.
«Class not found» al enlazar
El programa usa una clase de Java estándar que leJOS no incluye (por ejemplo, String.format o colecciones avanzadas). Reemplazarla por una alternativa simple.
El NXT se cuelga
Mantener presionados a la vez el botón naranja (ENTER) y el gris oscuro (ESCAPE) para reiniciarlo. Si no responde, quitar una pila unos segundos.
Memoria llena
Borrar programas viejos (archivos .nxj) desde el menú Files del NXT o con nxjbrowse.
